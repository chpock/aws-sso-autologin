# Добавление линтинга - product spec
Date: 2026-05-10
Author: Human Partner
Surfaces: developer-facing

## Problem
Сейчас в проекте нет настроенного линтера. Цель `make lint` содержит заглушку. Это приводит к:
- Отсутствию единого стиля кода
- Риску пропуска потенциальных ошибок на ранних этапах
- Необходимости ручной проверки стиля при code review

## Goals
1. Настроить линтер (ruff) для проверки кода Python
2. Интегрировать линтинг в процесс разработки
3. Запускать линтинг автоматически при тестировании
4. Обновить `make lint` для выполнения реальной проверки

## Non-goals
- Добавление type checking (отдельная задача)
- Изменение существующего стиля кода (только проверка)
- Интеграция с CI/CD (не настроено в проекте)

## Constraints
- Проект использует Python >=3.11
- Должно работать с существующим Makefile
- Должно использоваться в `prepare-dev` target

## Approaches considered

### Approach A - ruff (рекомендуемый)
- Современный линтер на Rust, заменяет flake8, black, isort
- Очень быстрый
- Встроенное автоформатирование
- Хорошая поддержка современного Python

### Approach B - flake8 + black + isort
- Классический набор инструментов
- Проверен временем
- Больше конфигурации
- Медленнее чем ruff

### Approach C - pylint
- Более строгие проверки
- Может быть слишком многословным
- Сложнее настроить

## Recommendation
Использовать **ruff** - это современное решение, которое заменяет несколько инструментов и работает быстро.
